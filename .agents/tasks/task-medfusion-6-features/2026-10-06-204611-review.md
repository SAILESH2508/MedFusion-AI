# MedFusion AI — Six-Feature Enhancement Implementation

This implementation adds Biomarker Trend Timeline, Explainable Risk, What-If Simulator, Emergency QR, Multilingual/Voice Explanation, and Light/Dark Theme to the existing MedFusion AI platform. The approach correctly reuses the existing architecture throughout: existing Django REST views and patterns, the existing axios `api` instance, existing CSS glassmorphism classes, and existing React component hierarchy. No new framework or database was introduced. The build passes clean on both Django (`System check identified no issues`) and Vite (`built in 1.73s`).

**Watch for:** `recharts` removed from `package.json` — confirm nothing downstream still expects it (confirmed: no `import.*recharts` found in source). `anthropic` and `cohere` packages removed from `requirements.txt` — those providers are also removed from `llm_provider.py`, so the dependency reduction is consistent. The emergency token is persisted in `localStorage`, which is acknowledged in an inline security comment in `Profile.jsx`.

**Verdict**: APPROVED

## High-level view

The six features are all present and behaviorally complete. Biomarker trends are computed client-side from the already-fetched `archive` prop in `MedicalVault`, requiring no extra network call, with a pure SVG chart and conservative direction labels. Explainable Risk uses `model.feature_importances_` from the actual trained Random Forest models, injected into the prediction response as a `factors` array alongside the existing `risk_score`/`risk_level` fields. The What-If Simulator calls the new `POST /api/predictions/simulate/` endpoint — distinct from `/predict/` — and the ML model path is executed; a rule-based inline fallback covers the case where the ML model file is absent. The Emergency QR system uses an `EmergencyToken` model with `is_active` deactivation on regeneration; the public `GET /api/emergency/{token}/` endpoint returns only name, vault ID, blood group, allergies, medications, and emergency contact — no email, password, or JWT fields. The VoiceExplainer handles `window.speechSynthesis` absence gracefully with a static fallback string, and translation errors keep the original text rather than failing silently. The theme system uses `data-theme` attributes on `<html>` backed by `localStorage`, with full CSS variable coverage for dark and light modes.

Two items are worth noting for future work: `recharts` was removed from `package.json` (it was present in the original baseline but never imported in any source file), and `anthropic`/`cohere` provider support was removed from `llm_provider.py` alongside their package entries in `requirements.txt`. Both are coherent cleanup decisions that reduce the attack surface and dependency footprint, but they change the declared interface relative to the original project spec (which listed those providers). Functionally, only Gemini and OpenAI remain active.

### Real ML feature importances, not fabricated

`_predict_using_ml` now returns `{score, factors}` instead of a raw float. After `model.predict()`, it calls `model.feature_importances_`, zips with the disease-specific `feature_names` list, sorts descending, and returns the top 5 — confirmed: `importances = model.feature_importances_`. The `factors` list flows into `predict_health_risk` via the fallback path, and into the Gemini path via an augmentation block that only fires when the Gemini response doesn't already carry a `factors` key. `run_prediction` appends `factors` to `record.to_dict()` before returning — not stored in `PredictionRecord`.

### Simulator uses actual ML model, not Gemini

`simulate_prediction` calls `ai_service._predict_using_ml(disease_type, parameters)` directly. The inline rule-based fallback only triggers when `ml_result is None` (model file absent), and returns an empty `factors` list rather than fabricating importances. No `PredictionRecord` is created. **Confirmed**: both `PatientDashboard` and `GuestDashboard` call `POST /predictions/simulate/`, not `/predictions/predict/`.

### Emergency QR security posture

`get_emergency_card` is decorated `@permission_classes([])` — no auth required, by design. The response contains: `name`, `vault_id` (a synthetic `MF-XXXXXX` identifier), `blood_group`, `allergies`, `active_meds` (name + dosage from latest prescription), `emergency_contact`, and `last_updated`. No `email`, no JWT, no `user.id` in raw form. The `EmergencyCard.jsx` frontend uses plain `axios`, not the JWT-intercepted `api` instance. Token generation uses `secrets.token_urlsafe(32)`, which is 32 bytes of URL-safe base64 — adequate entropy. Revocation sets `is_active=False`; regeneration deactivates all existing tokens for the patient before creating a new one via `EmergencyToken.objects.filter(patient=patient).update(is_active=False)`.

The token is persisted in `localStorage` keyed by user ID. An inline security comment in `Profile.jsx` acknowledges this trade-off explicitly, noting XSS risk and that the token only grants read access to non-sensitive fields. **Likely** concern: if the application ever introduces an XSS vulnerability, the token would be readable from JS. The comment suggests `sessionStorage` or a `GET /api/emergency/status/` endpoint as stricter alternatives. For the current threat model (the token conveys no auth capability and its data is already accessible to authenticated users), this is acceptable.

### Biomarker trends: client-side, no extra API call

The `/api/pathology/trends/` backend endpoint was implemented correctly (grouped by biomarker name, ordered by `created_at`), but the frontend chose not to use it. Instead, `MedicalVault.jsx` uses `useMemo` over the `archive` prop already passed by `Profile.jsx` — zero extra network requests. The direction-label logic is conservative: only `glucose`, `hba1c`, `cholesterol`, `ldl`, `triglycerides`, `creatinine`, `urea` are labeled lower-is-better; only `hdl` is higher-is-better; everything else becomes "Changed". With only one data point, "Stable" is returned. The disclaimer reads: "Direction labels reflect typical clinical conventions and do not constitute a diagnosis." The pure SVG chart handles ≥2 data points; single-point renders a static message rather than a degenerate chart.

### VoiceExplainer resilience

`hasSpeechSupport` is computed as `typeof window !== 'undefined' && !!window.speechSynthesis`. When `false`, the Listen button is replaced by "Voice not supported in this browser." Translation failures fall back to the original English text. The `text` prop change handler re-translates only when a non-English language is currently selected, preventing redundant API calls on every render cycle.

### Dependency changes

`recharts` removed from `package.json` — no `import.*recharts` in any source file. `leaflet` formally added (was already in `node_modules` and used). On the backend, `anthropic` and `cohere` are removed from both `requirements.txt` and `llm_provider.py`. This is a **possible** breaking change if the deployment environment previously relied on Cohere or Anthropic API keys — those keys will now be silently ignored and any code path that previously routed to those providers will fall back to Gemini.
