# MedFusion AI — Six-Feature Enhancement Implementation

Six features added to the existing Django + React 19 monorepo: Biomarker Trend Timeline, Explainable Risk, What-If Simulator, Emergency QR, Multilingual + Voice Explanation, and Light/Dark Theme. The backend work is concentrated in a single large commit (bca8633) that adds the EmergencyToken model, six new API endpoints, and refactors `_predict_using_ml` to return feature importances. Frontend work spans four subsequent commits covering dashboards, profile pages, and a new `VoiceExplainer` component. The implementation consistently avoids new npm/pip packages within the feature commits and all six features are present and wired correctly.

**Watch for:** (1) **confirmed** — scikit-learn was pinned to 1.9.0 in requirements.txt but the pickle models were trained with 1.3.2; every ML call fires `InconsistentVersionWarning` and results may diverge from training behavior. (2) **confirmed** — `react-leaflet` and `leaflet` appear in package.json but no JSX file imports them — dead dependencies adding bundle weight. (3) **confirmed** — `recharts` was removed during cleanup; no import breakage found in current source. (4) **possible** — `BiomarkerChart` silently returns null for single-point biomarkers, leaving the chart area blank with no explanation.

**Verdict**: CHANGES_REQUESTED

## High-level view

The backend additions are clean and well-separated from existing views. The six new endpoints are appended after a clearly marked `FEAT-001` comment block and the URL table orders `pathology/trends` before `pathology/` as required. The EmergencyToken model is minimal and correct.

The `_predict_using_ml` refactor returns `{score, factors}` and both the primary `predict_health_risk` Gemini path and the fallback path consume it, so feature importances flow all the way to the API response. However, the models were trained on scikit-learn 1.3.2 and the venv now runs 1.9.0; predictions still work in tests (score 65.0 returned correctly) but sklearn's own warning says results may be invalid, and the risk of silent divergence is real in a medical context.

The Emergency QR security boundary is correctly drawn: the public `/emergency/{token}/` endpoint returns only clinical emergency data (name, vault_id, blood_group, allergies, active_meds, emergency_contact, last_updated) — no email, password, or JWT. Token storage in `localStorage` keyed by user ID is acceptable for a convenience feature. The `OneToOneField` on EmergencyToken with soft-delete-before-create means regeneration is safe as long as the `update()` call completes before `create()`, which it will in a synchronous Django view.

The biomarker trend data is built entirely client-side from the already-fetched `archive` prop — no extra API call. The direction logic is medically conservative: only unambiguous biomarkers (glucose, HbA1c, cholesterol, LDL, triglycerides, creatinine, HDL) get Improving/Worsening labels; everything else becomes "Changed". The disclaimer at line 560 of MedicalVault reads "Recorded values shown in chronological order. Direction labels reflect typical clinical conventions and do not constitute a diagnosis."

The simulator calls `POST /api/predictions/simulate/` (confirmed at PatientDashboard line 702 and GuestDashboard line 598), never the `/predict/` endpoint, and the backend view explicitly does not call `PredictionRecord.objects.create()`. The disclaimer is present in both dashboard files.

`VoiceExplainer` handles `speechSynthesis` unavailability with an inline message. The fix commit (64e1b9c) added a `useEffect` that re-translates when the `text` prop changes, preventing the stale-translation bug where new prediction results would show the old language translation.

The pre-feature cleanup commit (0dce38e) removed `recharts` and `anthropic`/`cohere` from the project. The six-feature commits added nothing to package.json or requirements.txt. However, `leaflet` and `react-leaflet` are present in package.json from that cleanup commit with zero import sites in the current source, adding ~150KB to the bundle for no purpose.

<summary>Issues (4)</summary>

1. **scikit-learn version mismatch** — Models were pickled with 1.3.2; requirements.txt pins 1.9.0. `InconsistentVersionWarning` fires on every ML call. In a medical context, silent result divergence is unacceptable. Either re-train the models under 1.9.0, or pin back to `scikit-learn==1.3.2` in requirements.txt.

2. **Dead npm dependencies** — `leaflet` and `react-leaflet` are in package.json but no JSX file imports them. They inflate the install footprint and contribute to the chunk-size warning from Vite. Remove both entries.

3. **BiomarkerChart renders nothing for single data points** — The component returns `null` when `data.length < 2`. When only one report exists for a biomarker, the trend section shows no chart but also shows no message explaining why. A one-sentence fallback ("Only one data point — upload another report to see a trend") would prevent silent emptiness.

4. **Emergency token token-length exposure in localStorage** — The raw `secrets.token_urlsafe(32)` token (43 chars) is stored in `localStorage` under `medfusion_emergency_token_{userId}`. Any XSS vulnerability in the app could exfiltrate the token and expose the patient's emergency medical record to an unauthenticated attacker. This is a known trade-off for the convenience of remembering the token across sessions, but the security note should be documented; consider session storage instead, or re-fetching the token on profile load via a new `GET /api/emergency/status/` endpoint.

<summary>Details</summary>

### ML model version mismatch and prediction validity

`requirements.txt` pins `scikit-learn==1.9.0` but the three `.pkl` files in `ml_models/` were pickled under 1.3.2 (the sklearn warning identifies the stored estimator version on load). Running `model.predict()` and `model.feature_importances_` against the diabetes model with test inputs returns a plausible score (65.0%) and a valid importances array, so the API does not crash. But sklearn explicitly warns that results "might lead to breaking code or invalid results" across major versions. For a feature that feeds medical risk percentages shown to patients, silent divergence from training behavior crosses a medical safety threshold. This must be resolved before production: either re-train the three models using scikit-learn 1.9.0, or pin `scikit-learn==1.3.2` in requirements.txt (which matches what the models were built with).

### Dead dependencies in package.json

The cleanup commit introduced `leaflet` and `react-leaflet` into package.json alongside an `InteractiveMap.jsx` component. No route or JSX file in the current source imports from `react-leaflet`, and `InteractiveMap.jsx` is not imported anywhere either. These entries add two npm packages for zero runtime value and partially explain the chunk-size warning Vite emits at build time (`index-CQimVRcD.js` is 781KB).

### Emergency token storage model

The token is kept in localStorage keyed by `medfusion_emergency_token_{userId}`. This means a tab refresh restores the QR without a round-trip, which is the right UX decision. The security note is that localStorage is accessible to any script on the same origin. The application does not appear to have a CSP header configured in the Django settings, so XSS → token exfiltration → emergency record exposure is a realistic attack path. The token itself grants read-only access to non-auth fields (no email, no password), limiting blast radius. Documenting this trade-off in code comments is the minimum; upgrading to sessionStorage or a server-side token lookup on profile mount would close the gap.

### Single-point biomarker chart gap

`BiomarkerChart` guards `data.length < 2` with a `return null`. When a patient has uploaded exactly one pathology report containing a given biomarker, selecting that biomarker from the dropdown shows the statistics row (latest value, unit, status "Stable") but the chart area is blank with no explanation. A short "Not enough data for a trend chart" text in place of the null return would clarify this.
