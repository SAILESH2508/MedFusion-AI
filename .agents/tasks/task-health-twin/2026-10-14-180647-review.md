# 3D Personal Health Twin — MedFusion AI

The change removes the Health Garden feature from the UI, collapses the Quick Calc widget into a `<details>` element in the Doctor Dashboard, and introduces a new Patient-only `/digital-twin` route backed by a consolidated `GET /api/health-twin/` endpoint. The 3D organ viewer uses procedural Three.js geometry (no GLTF assets) loaded lazily. Four sub-components handle organ data, health timeline, medication safety, and biomarker comparison. All new patient-facing data surfaces read only from the authenticated user's own records — no fabricated values.

Watch for: (1) **confirmed** — `OrganInfoPanel` uses an `<a href>` tag instead of React Router's `<Link>` for the vault link, causing a full page reload on navigation; same pattern in `HealthTimeline`. (2) **confirmed** — the 3D canvas `onPointerMissed` handler is a no-op comment; clicking empty space never deselects the active organ, leaving the viewer in a state where all non-selected organ labels are suppressed with no way to clear. (3) **likely** — `MedicationSafetyPanel` sends `{ name, dosage }` objects to `/api/telemetry/drug-safety/` which likely expects string names; a mismatch would return a vacuously clean "No interactions detected" result.

**Verdict**: NEEDS_CHANGES

## High-level view

Health Garden removal is clean — `HealthGarden.jsx` is deleted, all nav items stripped from both the desktop and mobile `Navbar`, the `/garden` route is gone from `<Routes>`, `garden_views` is unregistered from `urls.py`, and `garden_views.py` plus the `HealthActivity`/`GardenProgress` models are intentionally preserved. No references remain in the frontend source tree.

The `<details>` wrapper around Quick Calc in `DoctorDashboard.jsx` is structurally correct, but the inner card still renders a redundant "Quick Calc" heading with its own `Calculator` icon directly below the already-icon-bearing `<summary>`. This means the expanded state shows the icon and label twice — a minor cosmetic gap but worth noting.

The `/digital-twin` route correctly guards for `user.role === 'Patient'` in `App.jsx` and redirects non-patients to `/auth`. The `isSidebarPage` string check includes `digital-twin`, the sidebar injection pattern follows the established `setSidebarContent` / cleanup return convention, and the 3D canvas is genuinely lazy-split by Vite into its own chunk (`OrganViewer3D-BFA6Zv45.js`).

`OrganInfoPanel` correctly scans `report_data` arrays using case-insensitive biomarker key matching and shows an empty state when no data exists; it does not generate reference ranges or values. `HealthChangeExplorer` has no backend calls, validates numeric input, and shows a persistent disclaimer — the non-saveable hypothetical value contract is enforced entirely in client state. `MedicationSafetyPanel` delegates all interaction logic to the existing `/api/telemetry/drug-safety/` endpoint rather than duplicating the INTERACTIONS engine from `utils.js`.

The `health_twin_view` backend function is decorated with `@api_view(['GET'])` and `@permission_classes([IsAuthenticated])`, returns 404 for non-Patient users, parses the `allergies` JSON field before sending (so the client receives an array), and makes no model changes. Django system check passes with 0 issues.

<summary>Issues (4)</summary>

1. **Full-page reload on vault navigation** — `OrganInfoPanel` uses `<a href="/profile?tab=vault">` and `HealthTimeline` uses `<a href="/profile?tab=vault">` instead of React Router `<Link to>`, causing a full page reload and session disruption. Replace with `import { Link } from 'react-router-dom'` and `<Link to="/profile?tab=vault">`.

2. **No way to deselect an organ** — `OrganViewer3D` has `onPointerMissed={() => {/* deselect handled in parent */}}` but `DigitalTwin.jsx` never calls `setSelectedOrgan(null)` anywhere; the comment is a false promise. When an organ is selected, all other organ labels are hidden and there is no escape back to the full-body view. Wire the `onPointerMissed` canvas prop to `() => setSelectedOrgan(null)` in `DigitalTwin.jsx`.

3. **`drug-safety` payload shape mismatch** — `MedicationSafetyPanel` posts `{ medications: currentMeds }` where `currentMeds` is `Array<{ name, dosage }>`. If `check_drug_safety` expects string names (`['Metformin', 'Lisinopril']`), objects will coerce to `[object Object]` and all lookups miss, returning a falsely clean result. Confirm the expected payload shape and normalise `currentMeds` to `currentMeds.map(m => m.name)` if needed.

4. **Duplicate header inside expanded Quick Calc** — After expanding the `<details>` element, users see both the `<summary>` row ("Clinical Calculators" + Calculator icon) and the existing inner card header ("Quick Calc" + Calculator icon). The inner header became redundant once the `<details>` summary took that role. Remove the inner `<h4>Quick Calc</h4>` heading row and keep only the `<summary>`.

## Quick Calc — duplicate header on expand

The `<details className="glass-card">` wrapper at line 378 of `DoctorDashboard.jsx` has the `<summary>` carrying the `Calculator` icon and "Clinical Calculators" label with no `open` attribute. The inner widget retains its own header row with a second `Calculator` icon and "Quick Calc" `<h4>`. When expanded, the user sees the icon and label twice — once in the `<summary>` and once in the first row of the expanded content.

## Organ deselect gap

`OrganViewer3D` passes `onPointerMissed={() => {/* deselect handled in parent */}}` to the Canvas, but `DigitalTwin.jsx` provides `onOrganSelect={setSelectedOrgan}` and nowhere calls `setSelectedOrgan(null)`. The comment implies deselect logic that was never wired. When an organ is selected, `SingleOrgan` and `PairOrgan` both suppress labels for non-selected organs (`isHidden = selectedOrgan !== null && !isSelected`), so the viewer becomes a view of one highlighted shape with no visible route back to the full-body overview without refreshing. **Confirmed** by tracing `onPointerMissed` through both files — no handler sets `selectedOrgan` back to `null`.

## Vault navigation: `<a>` vs `<Link>` — confirmed reload path

`OrganInfoPanel.jsx` line ~119: `<a href="/profile?tab=vault">View in Medical Vault →</a>`.  
`HealthTimeline.jsx` line ~139: `<a href="/profile?tab=vault">View full record →</a>`.

Both use a raw anchor tag. In a React Router SPA this triggers a full page reload — the current patient data fetch, sidebar state, and selected organ are all lost. The fix is a single-import change to `Link` from `react-router-dom`. `DigitalTwin.jsx` already imports from `react-router-dom` via `Navigate` in `App.jsx`, and all other nav in the app uses `RouterNavLink`. This is a confirmed regression relative to the app's established navigation pattern.

## Medication safety payload shape — likely false-clean result

`MedicationSafetyPanel.jsx` calls `api.post('/telemetry/drug-safety/', { medications: currentMeds })` where `currentMeds` is `Array<{ name: string, dosage: string|null }>`. If `check_drug_safety` expects string names, objects will silently coerce to `[object Object]` in Python's JSON parsing and all interaction lookups will miss, returning a falsely clean result which the panel displays as the green "No known interactions detected" state.

## HealthChangeExplorer — reference range parsing gap

The `reference_range` parser handles `"3.5 - 5.0"`, `"3.5–5.0"` (en-dash), `"< 5.0"`, and `"> 0.5"` via regex. Formats with units embedded in the range string (e.g. `"< 5.0 mmol/L"`) won't match the `[\d.]+` capture group and will return `null`, displaying "Unable to assess" — the correct fallback, but worth knowing if the pathology import produces that format.

## Backend health_twin_view — Doctor leakage absent

`Patient.objects.get(user=user)` returns 404 for any user without a Patient record. Doctors never have a Patient record, so the endpoint is correctly siloed. The `allergies` field is `json.loads(patient.allergies or '[]')` before serialisation — clients receive a list, not a raw string.

## Test coverage

No automated tests exist in this project. The organ deselect path, vault link navigation, and drug-safety payload shape are the three gaps most likely to be caught only at runtime.
