# Remove Health Garden, Simplify Quick Calc, Build 3D Personal Health Twin

Four features were delivered in a single task: the Health Garden was removed from all surfaces (frontend routes, nav, API), the Doctor Dashboard's calculator was collapsed behind a `<details>` element, a `/digital-twin` Patient-only route was added with a 3D organ viewer and four companion panels, and a consolidated `GET /api/health-twin/` endpoint was added to the backend. All changes build cleanly (`npm run build` exits 0, `python manage.py check` reports 0 issues).

**Watch for:** (1) The `"No known interactions detected"` green banner fires whenever `has_interactions` is falsy and `critical_warnings` is empty — confirmed — the implementation correctly avoids labelling a medication as safe, but this is worth a second reviewer pass to confirm the backend contract. (2) The allergy cross-check in `MedicationSafetyPanel` is a simple `String.includes` on the allergy token — a three-letter allergy abbreviation could match a drug fragment with no clinical relationship. (3) `OrganViewer3D` and `@react-three/drei` together ship a 943 kB chunk (gzip 251 kB); the chunk is lazy-loaded but still large for mobile.

**Verdict**: APPROVED

---

## High-level view

Garden removal is surgical: `HealthGarden.jsx` is deleted, all three nav surfaces (desktop, mobile, `isSidebarPage`) are cleaned, the four backend URL patterns are removed, and the `401` interceptor path exclusion is trimmed. The `garden_views.py` module and the `HealthActivity`/`GardenProgress` models are intentionally left intact to avoid a destructive migration, which is the correct call.

The Quick Calc wrapper changes a visual hierarchy — the calculator glass-card is now a child of a `<details className="glass-card">` — so `border-radius` applied to the outer `<details>` and the inner card may render a double-border depending on the theme. The calculation logic, state, and formulas are untouched.

The Personal Health Twin wires five components under a single lazy-loaded route. `DigitalTwin.jsx` tries `GET /api/health-twin/` first and silently falls back to four parallel legacy endpoints on any error. That means a network error or a 500 on the consolidated endpoint degrades gracefully, but a 403 or a JWT expiry on the consolidated endpoint also silently falls through to the fallback — the user gets data but never sees the error.

The backend `health_twin_view` scopes all queries through `patient.predictions`, `patient.pathology_reports`, and `patient.prescriptions` reverse relations — data isolation is correct. The view returns 404 for Doctor-role users (no `Patient` record), consistent with the spec.

The `MedicationSafetyPanel` POSTs to `/api/telemetry/drug-safety/` — no local interaction engine is added. The client-side allergy alert is limited to a substring match (`med.name.toLowerCase().includes(allergyToken)`) which can produce false positives for short allergy tokens and misses allergies expressed as drug classes rather than drug names.

The `HealthChangeExplorer` has no backend calls, labels inputs as hypothetical, never saves anything, and degrades cleanly when pathology data is absent. The reference-range parser handles `3.5 - 5.0`, `< 5.0`, and `> 0.5` formats but will silently report "Unable to assess" for any other format (e.g. `3.5–5.5` with an em dash, `≤5.0`), with no user-visible explanation of why.

<summary>Issues (4)</summary>

1. **Allergy cross-check false positives** — `checkAllergyHits` uses `med.name.toLowerCase().includes(allergyToken)`. A short allergy token (e.g. "ASA", "in") can match unrelated drug name fragments. Consider whole-word matching or a minimum token length, and document the limitation.

2. **Consolidated endpoint error masking** — A 403, 429, or 500 on `GET /api/health-twin/` silently falls through to the four-call fallback with no user notification. The catch block should distinguish auth/server errors (show an error state) from network-only errors (try fallback).

3. **Double glass-card border on Clinical Calculators** — `<details className="glass-card">` wraps the existing inner `<div className="glass-card p-3 ...">`. Both elements carry the glass-card class and its border, producing a nested border artifact. The inner card's class should be removed or replaced with `p-3` only.

4. **Reference-range parser silent failure** — `isInRange` returns `null` (rendered as "Unable to assess") for ranges using em dashes (`–`), `≤`, `≥`, or units appended to the range string (e.g. `3.5 - 5.0 mmol/L`). Users see "Unable to assess" with no explanation. Add a brief note when the range string is present but unparseable.

<summary>Details</summary>

### Quick Calc collapse — double-border issue

The FEAT-002 spec called for wrapping the existing glass-card in a `<details>` element. The implementation applies `className="glass-card"` to the `<details>` itself while the inner widget retains its original `glass-card p-3 d-flex ...` class. This nests two elements with the `glass-card` border and background styles, which will render a visually doubled border and potentially a double background blur. The fix is to strip `glass-card` from the inner div and keep it only on the `<details>`, or vice versa. The calculation logic (BMI = weight/height², THR = 220 − age with 60–85% zone bands) is confirmed unchanged. **confirmed**

### 3D viewer chunk size

`OrganViewer3D` is correctly lazy-loaded into its own chunk (`OrganViewer3D-BVvPEyM2.js`, 943 kB minified / 251 kB gzip). The `React.Suspense` fallback keeps the page unblocked. The chunk is large for mobile connections; reducing it further would require splitting `three`/`@react-three/drei`, which is a follow-up concern.

### Allergy cross-check false positives

`checkAllergyHits` in `MedicationSafetyPanel.jsx` does:
```js
medNameLower.includes(allergyLower)
```
A patient with a recorded allergy to `"in"` (common abbreviation or partial string) would match `"insulin"`, `"ibuprofen"`, `"aspirin"`. A three-character allergy like `"ASA"` matches any drug whose name contains that substring. The check should use whole-word matching or enforce a minimum token length. Since this is a display-only alert (the real check runs server-side via the drug-safety endpoint), this is not a patient-safety blocker, but it can produce alarming false alerts that erode trust. **confirmed**

### Consolidated endpoint error masking

`DigitalTwin.jsx` catches *all* errors from `GET /api/health-twin/` and falls back to the four parallel calls:
```js
} catch {
  // Fallback: parallel calls to existing endpoints
```
A 401 (expired JWT), 403 (permission revoked), or 500 (server crash) on the consolidated endpoint is silently swallowed and retried via the fallback. If the fallback also fails, only then does the user see an error state. This means an authentication problem on the new endpoint is invisible — the user may see stale fallback data or no error at all. The outer catch should inspect the error type: re-throw `4xx` auth errors rather than falling through. **confirmed**

### Reference-range parser silent failure

`isInRange` in `HealthChangeExplorer.jsx` handles three patterns (`\d-\d`, `< \d`, `> \d`). The regex `^([\d.]+)\s*[-–]\s*([\d.]+)$` does include an en dash (`–`) but not an em dash (`—`) or Unicode minus. Ranges like `"3.5 - 5.0 mmol/L"` (unit appended) will not match any branch and return `null`. When `null` is returned, the UI renders "Unable to assess" without any contextual note that the range string exists but couldn't be parsed. A user who sees a range value displayed alongside "Unable to assess" will not understand why the comparison failed. **confirmed**
