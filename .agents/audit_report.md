## 2. HARDCODED PLACEHOLDER FALLBACKS

### 2.1 `views.py` — `list_patients` response builder

**File:** `backend/medical/views.py` (lines ~775–790)  
**Finding:** Patient fields are returned with hardcoded fallback strings that will appear verbatim in the Doctor Dashboard if a patient's profile is incomplete:

| Field | Hardcoded fallback | Risk |
|---|---|---|
| `dob` | `"1995-08-12"` | Fabricates a birth date |
| `gender` | `"M"` | Fabricates a gender |
| `blood_group` | `"O+"` | Fabricates a blood type |
| `emergency_contact` | `"+91 9876543210"` | Fabricates a real-looking phone number |

These should return `null` (or be omitted) when the field is not set, so the UI can display a "Not recorded" placeholder instead of fake data.

```python
# BEFORE (dangerous — fabricates clinical data)
"dob": p.dob.isoformat() if p.dob else "1995-08-12",
"gender": p.gender or "M",
"blood_group": p.blood_group or "O+",
"emergency_contact": p.emergency_contact or "+91 9876543210",

# AFTER (safe — returns null)
"dob": p.dob.isoformat() if p.dob else None,
"gender": p.gender or None,
"blood_group": p.blood_group or None,
"emergency_contact": p.emergency_contact or None,
```

### 2.2 `views.py` — `add_manual_prescription` physician fallback

### 3.1 Doctor Dashboard: no patient search/filter

**File:** `frontend/src/pages/dashboard/DoctorDashboard.jsx`  
**Finding:** The Patient Directory Console renders all patients as a flat scrollable list with no search input or filter. For a practice with many patients, finding a specific record requires manual scrolling. A simple controlled `<input>` filtering on `p.name` and `p.email` would fix this.

**Suggested implementation:** Add a search state variable and filter the `patients` array before rendering:

```jsx
const [search, setSearch] = useState('');
const filteredPatients = patients.filter(p =>
  p.name.toLowerCase().includes(search.toLowerCase()) ||
  p.email.toLowerCase().includes(search.toLowerCase())

```

**Finding:** The profile sidebar (rendered via `setSidebarContent`) contains the Medical Vault and Health Score panels but no logout button. Users who navigate to Profile expecting account controls cannot log out from there. A logout button should be added at the bottom of the sidebar content.

### 3.3 No PDF export of prediction report

**File:** `frontend/src/pages/dashboard/GuestDashboard.jsx`  
**Finding:** The result panel has a print button (`handlePrint` → `window.print()`). This opens the browser print dialog but has no custom print stylesheet, so the printed/saved PDF will include the entire app chrome (sidebar, nav). A proper PDF export should either:
- Use `window.print()` with a `@media print` stylesheet that hides everything except the result panel, or
- Use a library like `html2pdf.js` or `jsPDF` to export only the result card.

### 3.4 Upload page: no drag-and-drop support

**File:** `frontend/src/pages/Upload.jsx`  
**Finding:** The upload zone says "DROP RX PRESCRIPTION HERE" / "DROP PATHOLOGY LAB REPORT HERE" but the `<div>` only has an `onClick` handler — there are no `onDragOver`, `onDragEnter`, or `onDrop` event handlers. The drop target is entirely non-functional for drag-and-drop. The hidden `<input type="file">` only opens via click. The UI copy is misleading.

**Fix:** Wire up `onDragOver={e => e.preventDefault()}`, `onDragEnter`, and `onDrop={e => { e.preventDefault(); handleFileChange({ target: { files: e.dataTransfer.files } }); }}` on the upload zone `<div>`.

### 3.5 NearbyMap: radius slider does not re-fetch

**Finding:** The radius control in the NearbyMap / patient dashboard allows the user to change the search radius, but the fetch guard `if (places.length > 0) return` prevents a re-fetch once places have been loaded. Changing the radius has no visible effect. The guard was added to prevent refetching on every re-render, but it also blocks intentional radius changes.

**Fix:** Track `radius` as part of the fetch dependency (e.g. store the radius that was used for the last fetch as a ref, and trigger a re-fetch when the user-selected radius differs from it).

### 4.2 `InteractiveMap.jsx` — `tileRef` not cleaned up on hybrid layer switch

**File:** `frontend/src/components/InteractiveMap.jsx`  
**Finding:** When `tileLayer === 'hybrid'`, the effect adds two tile layers to the map (satellite base + OSM humanitarian label overlay) but only stores the satellite layer in `tileRef.current`. On the next tile-layer change, only the satellite layer is removed; the label overlay layer is leaked and accumulates. This results in stacked label overlays when the user toggles the layer multiple times.

**Fix:** Keep a ref array `tileLayersRef` for all active tile layers and remove all of them on each tile switch.

### 4.3 `InteractiveMap.jsx` — map not preserved across navigation (re-mount)

**File:** `frontend/src/components/InteractiveMap.jsx`  
**Finding:** The Leaflet map is initialized in a `useEffect` that runs once on mount (`if (mapRef.current) return` guard). However, when the user navigates away and back, the component unmounts and remounts, and the cleanup function (`mapRef.current.remove()`) destroys the map. On remount the component receives `location` and `places` from the parent, but if the parent also re-fetches places on remount, the user sees a full reload. The solution is to lift map state (location + places) to the parent and preserve it in `localStorage` or context so the parent can skip the re-fetch when returning to the map page.

### 4.4 `views.py` — `add_manual_prescription` missing `return` statement

**File:** `backend/medical/views.py` (lines ~840+)  
**Finding:** The `add_manual_prescription` view creates the `Prescription` object but the visible code block ends without a `return JsonResponse(...)` statement in the shown lines. If the function ends without a return, Django will raise a `ValueError: The view ... didn't return an HttpResponse`. Verify the return statement exists below the visible truncation point and add one if missing:
